    Inter-row vegetation analysis¶

    This document provides notes and instructions for analyzing inter-row vegetation cover in vineyards and comparing results with internal data.

    Note: In all provided configurations, paths to data have been left as-is. You will need to edit them to match data on your desired environment.

    Previous work by Fajwel¶

    Note: The script haies_spectral_indices could not be run successfully, but is documented here for completeness and reference.

    This workflow was designed to compute spectral indices on a grid for vineyard regions using LiDAR and satellite imagery.

    Usage¶

    haies_spectral_indices

    Configuration¶

    The script uses get_spectral_indices_on_grid.yaml, which specifies: - LiDAR and ortho imagery paths - RPG vineyard parcel selection criteria - Sentinel-2 data directory and date range - Output resolution and save directory

    Processing steps¶

    1. Process vineyard regions specified in the configuration
    2. Create masks to identify areas between vine rows using LiDAR height data
    3. Compute spectral indices (EXG, GLI, NDVI) from both aerial and Sentinel-2 imagery
    4. Save results as both raster files and vector data (parquet/GeoJSON)

    Reproducing Fajwel's inter-row analysis in La Bataille region¶

    This workflow masks rows of vines in the La Bataille region, computes spectral indices, and compares aggregated values between fully-cultivated and half-cultivated parcels.

    Required data¶

    • BDOrtho imagery (note the precise acquisition dates)
    • Height output from model (LiDAR-derived)
    • Parcel polygons
    • Internal cultivation data

    Ensure that dates match between imagery and reference data.

    Workflow overview¶

    1. Determine AOI based on internal data in La Bataille region
    2. Create dataset of height data and BDOrtho data masked to parcel boundaries
    3. Create per-parcel vine row mask using minimum height as a filter
    4. Apply vine row mask on BDOrtho data
    5. Calculate spectral indices on masked data
    6. Compare parcels by cultivation type (fully-cultivated vs. half-cultivated)

    Step 1: Create datasets masked to parcel boundaries¶

    This script masks raster data (height and BDOrtho) to individual parcel polygons and saves them as separate TIF files per parcel.

    python src/haies/spectral_indices/mask_raster_by_polygons.py

    Step 2: Compute GLI on masked parcels¶

    This script applies binary erosion to remove edge artifacts, computes GLI from RGB imagery, and aggregates results by zone and cultivation type.

    python src/haies/spectral_indices/compute_masked_gli.py

    Note on biomass calculation: This script also calculates the estimated areas of masked parcels, which can be used for biomass estimation. Example output:

    Sentinel-2 time series analysis¶

    This section covers downloading Sentinel-2 imagery, extracting time series statistics per parcel, and performing cluster analysis to identify vegetation patterns.

    Download data¶

    Download Sentinel-2 imagery using the geefetch library. See the documentation for installation instructions.

    Usage¶

    geefetch s2 -c src/configs/geefetch_cognac.yaml

    Configuration¶

    The geefetch_cognac.yaml configuration specifies: - AOI spatial extent (UTM 30N coordinates covering the Cognac region) - Temporal range (e.g., 2022-05-01 to 2024-04-30) - Selected bands: B2, B3, B4, B5, B6, B7, B8, B8A, B11, B12 - Cloud filtering parameters - Output resolution (10m) and tile size

    Important notes on cloud parameters¶

    Pay close attention to cloud filtering settings in the geefetch s2.py script, particularly lines 129 and 164. Incorrect cloud parameters can result in missing or poor-quality (cloudy) data.

    Extract Sentinel-2 time series per parcel¶

    This script extracts per-zone time series of vegetation-related indices from Sentinel-2 imagery.

    Example output¶

    Usage¶

    haies_sentinel_timeseries

    Configuration¶

    Edit extract_sentinel_timeseries_config.yaml to specify: - sentinel_dir: Directory containing Sentinel-2 time series images - polygons_path: Path to KML or GeoJSON file containing parcel polygons - save_dir: Output directory for results - band_names: Sentinel-2 band mapping (B2-B12) - Processing flags: extract_timeseries, interpolate_timeseries, aggregate_by_zone, create_zone_plots

    Override parameters on the command line:

    haies_sentinel_timeseries extract_timeseries=false create_plots=true

    Processing steps¶

    1. Load polygons from a KML file (or other vector format)
    2. Extract mean, std, min, max, and median values for each Sentinel-2 band
    3. Compute vegetation indices (NDVI, NDRE, GLI, NDWI)
    4. Process all time steps to create a time series for each polygon
    5. Interpolate time series to regular intervals
    6. Save results as parquet and CSV files with optional pivot tables for visualization

    Cluster analysis¶

    This workflow identifies natural groupings in vegetation index time series using k-means clustering to discover phenological patterns across parcels.

    Step 1: Extract time series over larger area¶

    Extract Sentinel-2 time series for all parcels within a 20 km region in the Charente region using the expanded configuration.

    haies_sentinel_timeseries -cn extract_sentinel_timeseries_config_all_parcels

    This uses extract_sentinel_timeseries_config_all_parcels.yaml, which includes all vineyard parcels from the regional GeoJSON rather than just internal parcels.

    Step 2: Run cluster analysis¶

    Apply k-means clustering to the interpolated time series data.

    haies_cluster_timeseries

    Configuration¶

    Edit cluster_timeseries_config.yaml to specify: - save_dir: Directory containing interpolated time series parquet file - index_column: Vegetation index to cluster on (e.g., NDVI_median, GLI_median) - n_clusters: Number of clusters (optional, auto-determined if not specified) - k_min, k_max: Range of k values to test for optimal cluster selection

    Processing steps¶

    1. Load interpolated time series data
    2. Pivot data to create a feature matrix (parcels x time steps)
    3. Standardize features using z-score normalization
    4. Determine optimal k using silhouette score (if not specified)
    5. Apply k-means clustering
    6. Generate cluster centroid plots and sample time series visualizations
    7. Export cluster assignments for further analysis
